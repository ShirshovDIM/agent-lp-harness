findings

Honest results — even when unflattering

The verifier publishes what the replay says, including when the result beats the author’s own position. In this window, simply holding won.

1Tick-grid geometry dominates

On the USDC-AERO grid one cell moves price by ~22 %. There a “small-swap” re-range is geometrically impossible — it equals the full swap on all 113 starts (difference 0.00 USD). On the fine CL50 grid no-swap modes win medians, but pay for it with p90 = 5–12 rewardless days per start.

2The swap is the dominant cost on a thin pool

Re-range with real curve slippage (pool ≈ $6.5k TVL, ~2.3 % per reference swap): median −88.12 % at ±2 % width and −0.06 % at ±30 %, against hold ±30 % at +5.15 %.

3Fee sensitivity is second-order

Raising the swap fee 0.05 % → 0.6 % moves median differences between modes by under 1 USD per reference position. Width and grid geometry matter more than the swap decision itself.

Said plainly: HODL 50/50 on the same Celo window returned a median +8.15 % — above every LP mode in the table (best hold ±30 %: +5.15 %). In a rising window the LP value is fee income, not price capture.

Statistics, stated rather than hidden: the 113 starts overlap — n_eff ≈ 2.2 independent windows — and tail probabilities carry near-zero Wilson lower bounds. Directional numbers, published with their caveats.

run it

Verify any position — including yours

The verifier reads the position from Celo on-chain; nothing is hand-entered. Deterministic: seed 113, no LLM in the measurement loop.

Verify any position

python3 scripts/verify.py --position <tokenId> --mint-tx <hash>

Reads the position from Celo on-chain and emits the report. Source: scripts/verify.py.

Recompute the published measurement

python3 scripts/celo_fetch.py --days 30 && python3 scripts/celo_report.py

Fetches 30 days of hourly on-chain samples and rebuilds the Celo measurement end to end.

report format

Every report states five things

The format is part of the verification: if a claim cannot be traced to a window, a method and a calibration, it does not get published.

  1. WindowExact UTC bounds of the data and the market regime those hours cover.
  2. MethodHow the position, fees, rewards and costs are computed from on-chain state — with the script names that did it.
  3. StatisticsMedians, p10/p90, tail probabilities, and the effective number of independent windows behind every claim.
  4. CalibrationModel output reconciled with rewards actually claimed by a live position, citing the on-chain claim event.
  5. CaveatsStated, not hidden: regime bias, overlapping starts, approximations.
